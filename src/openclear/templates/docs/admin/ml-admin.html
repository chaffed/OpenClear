ML Scoring & Default Disposition

Two separate settings. Fraud scoring is your organization's: an advisory score beside each exception, from a model trained on your own decisions. The default decision is set per customer and per payment network (check and ACH separately): what happens if nobody decides an exception in time.

{{ docs.screenshot("admin_ml_models", "ML models admin screen") }}

Fraud scoring

Fraud scoring is off until you turn it on in Settings → Fraud scoring. Turning it on or off is a sensitive change: when sensitive settings need a second admin, it waits for one. With it off, nothing is trained or scored.

  • The score is advisory. It shows on each exception and in the list, and a person always makes the call. It never decides an item, by default or otherwise.
  • Your model learns only from your own organization's final decisions. Your data is never shared with another bank, and there are no separate models per customer.
  • Your administrators retrain and activate models in Settings → ML models. Your first model is activated when it's trained. A retrained version replaces the active one only once it has learned from enough of your decisions (200 by default) and scores at least as well on your most recent ones. Otherwise it's kept, with the reason shown, and can be activated by hand.

Default decision

From a customer's page, open Default decision to set what happens when an exception's decision cut-off passes with no human decision: leave it open (the default), or a fixed pay or return outcome. For ACH, set the default return reason to use. The cut-off itself is the bank's, or one agreed with the customer (see Decision cut-off). An ACH return with no default return reason is skipped rather than guessed: the item stays open for a person.

When sensitive settings need a second admin, choosing pay as a customer's default waits for someone else to approve it, as the cut-off does: it pays items nobody looked at. Leaving items open, or returning them, applies at once.

A scheduled sweep applies these defaults to any exception whose cut-off has passed; decisions it makes are marked as automatic in the audit log and exception history, so they're always distinguishable from a human's decision.
