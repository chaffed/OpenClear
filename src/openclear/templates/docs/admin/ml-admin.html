ML Scoring & Default Disposition

Two related settings, both configured per customer and per payment network (check and ACH separately): how confident the fraud model needs to be before a score is shown, and what should happen automatically if nobody responds to an exception in time.

{{ docs.screenshot("admin_ml_models", "ML models admin screen") }}

Shared or bank-only model

Your organization chooses its fraud-scoring model in Settings → Fraud scoring model:

  • Shared model (every organization starts here). It learns from the decisions of every participating bank, so it's useful from day one. The platform operator trains it and decides which version is active; your Admin page shows its version and how many decisions and banks it learned from, but never which banks. Your fraud-training examples are used by it only after the platform operator reviews them.
  • Bank-only model. It learns only from your own decisions, so your data never leaves your organization. When you switch, it starts as an exact copy of the shared model, so scoring continues without a gap. Your administrators then retrain it from Admin. A retrained version replaces the active one only once it has learned from enough of your decisions (200 by default) and scores at least as well on your most recent ones. Otherwise it's kept, with the reason shown, and can be activated by hand.

New organizations stay on the shared model for their first 90 days. The page shows when you can switch. Switching back to the shared model is always allowed, but first someone must acknowledge how the shared model uses your data. Every switch and acknowledgement is recorded in the audit log.

Per-customer scoring mode

From Admin, open a customer's ML settings to choose its scoring mode for each network: Auto (its own model once one is trained, otherwise your organization's model), Bank's model (always your organization's model), or This customer's model. The page shows which model is scoring the customer right now. Customer models are retrained and activated there too.

Default disposition

Set what happens when an exception's response window closes with no human decision: a fixed pay or return outcome, or let the ML model's score decide. You also configure the response window itself (in hours) and, for ACH, the default return reason to use. If ML-determined disposition is selected but there isn't yet enough model data to score an item, it's skipped rather than guessed — it stays open for a human to review rather than risk an under-informed automatic decision.

A scheduled sweep applies these defaults to any exception whose window has expired; decisions it makes are marked as automatic in the audit log and exception history, so they're always distinguishable from a human's decision.
