A layout tells OpenClear how to read a file that isn't in OpenClear's own column format: which column (or which characters, in a fixed-width file) holds each field, and how amounts and dates are written.

{% if ctx.customer_id is none %}
  • Issued checks: the checks a customer has written: account, check number, amount, date and payee.
  • Posted checks: the file your core sends of the checks it posted, for every customer at once. Only your bank's staff build these. A layout can name the file's trailer: when its item count or total doesn't match the lines, the whole file is refused, so a truncated file never presents half a day's checks.
{% endif %}

Build one from a sample of your file. Each upload records the layout it used, so changing a layout later doesn't change what an earlier upload meant.

The default layout is chosen for you when you upload, and is the one the dropbox reads with. A customer's own default comes before the bank's.
