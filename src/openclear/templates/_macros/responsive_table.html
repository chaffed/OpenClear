{# One table that reads as cards on a phone (MOBILE_PLAN.md §1). It stays a real table, so screen readers, sorting, CSV export and the server-side list filters all keep working; CSS (app.css "Responsive tables") does the rest. On a desktop it renders what a hand-written table would. columns: a list of dicts, one per column: key what the caller block switches on label the header, and the "label:" before a meta value on a card role primary (the card's title), money (beside the title), status (a badge line), meta (a "label: value" line), text (a line of its own, no label), actions (the card's footer), select (a checkbox in the card's corner) sort a server-side sort key (web/list_search.py), when `search` and `action` are given numeric True for a column that sorts as a number hide "phone" or "tablet": dropped below that width (the item's own page has it) sheet actions only: on a phone, a ⋯ button opening the actions in a bottom sheet (for more than two); "tablet": below desktop th extra header attributes, as a string without quotes (data-no-sort) th_class classes for the header cell header True: the caller block renders the header too, called with part="header" (a select-all checkbox) class extra cell classes row_attrs: attributes for every row, as a string (data-row-link, for the J/K keys). The caller block renders a cell: {% call(row, col, part="cell") responsive_table(...) %}.
